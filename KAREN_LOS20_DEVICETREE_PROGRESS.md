# karen LOS20 device tree — progress log

OnePlus Nord 2T (RMX3031/CPH2401/OP557A, codename `karen`), LineageOS 20 / Android 13.
Ground truth for every device value: the A13 OxygenOS dump at `D:\ossi-karen-dump`
(`/mnt/d/ossi-karen-dump` in WSL). Reference (structure only, values must be re-verified
against the dump): `mt6893-development/android_device_oplus_op6893` (denniz, same MT6893
platform but A-only with a recovery partition — karen is virtual A/B, recovery-as-boot).

## Verified device facts (from the dump)

### Hardware inventory (DeviceInfo HW report from this CPH2401 unit, OOS12 era)

Useful for the HAL/sepolicy bring-up phase:

- SoC MT6893 (Dimensity 1300), board k6893v1_64, device OP557AL1, 8 GB LPDDR4X, UFS.
- Cameras: IMX766 + IMX615 + IMX355 + GC02M1b — all `*_raw21881` (live confirmation of
  project 21881 = karen).
- Touch: FocalTech FTS (i2c 0-0038). Fingerprint: anc_mtk (spi1.0). NFC: NXP pn544
  (i2c 9-0028). SmartPA: aw882xx.
- Sensors: Bosch BMI2XY (accel+gyro), MEMSIC mmc5603 (mag), AMS tcs3701 (ALS/PS).
- Charging: mp2650 + rt5125 + bq27541 gauge; mt6360 PMIC companion (main PMIC remains
  MT6359P per the dump DT). USB-C switch: fsa4480. Panel: 1080x2400 @ 60/90 Hz.
- Features declare face + fingerprint biometrics (camera-based face unlock).
- The report is from OOS 12 (A12, kernel 4.14.186, Oct 2022): the OOS 13 OTA upgraded
  the kernel to 4.19.191 and also flashed preloader_raw/lk (stock OTAs write the whole
  bootloader chain) — the device now runs A13-era bootloader firmware, which is exactly
  what our A13 dump prebuilts are paired with, and one more reason our ROM must never
  touch the preloader.
- Variant note: this unit is CPH2401 (India); CPH2399 is the EU/Global karen variant (same
  hardware family; odm carries both 21881 and 21882 conf variants) — the OTA assert intentionally allows both.

- Virtual A/B **with compression**, recovery-as-boot, boot header **v2**, no vendor_boot,
  no cache/recovery partitions. Stock kernel is an **uncompressed Image**, 4.19.191+, clang 11.
- Partition sizes (exact image dumps): boot 67108864, dtbo 716800, super 10200547328,
  main group 10196353024 (system system_ext vendor product odm only — my_* partitions are
  NOT built; fstab keeps their nofail entries).
- Stock fingerprint: `OnePlus/CPH2401/OP557AL1:13/TP1A.220905.001/S.ef7649_3761f:user/release-keys`
  (VENDOR_SECURITY_PATCH 2023-03-05, first API level 31, VNDK 31 / sepolicy 31.0).
- VINTF: 46 HALs; manifest is stock-equivalent (target-level 5). ODM declares radio/mtkradioex/
  secure_element/oplus HALs via manifest_dsds/manifest_ss (ship with the odm image).
- Vendor partition dump was restored from the dump repo git history (`git checkout --
  vendor_extracted system_ext_extracted`) — extraction now finds every blob (2520 entries).

format) + `Image.gz` build clean with `MODPOST 0 modules`.**

The stock karen defconfig needed four fixes to compile against the denniz-evolved 4.19

   built-in drivers/misc/mediatek/accdet/mt6359 driver — enabling the sound/soc codec
   copy caused duplicate-symbol link errors. The device tree ships no kernel modules,
   so the Image is fully self-contained.

One-command build (validated): `wsl -d Ubuntu -- bash ~/karen/build-karen-kernel.sh`
Backups: `D:\work\android_kernel_oplus_karen` (glm synced to d53638a3) and
`D:\work\kernel-karen-glm.bundle`.

Build recipe that reached the final vmlinux link stage (toolchain: clang r498229b):
```
PATH=~/karen/hostdeps/root/usr/bin:~/karen/toolchains/clang-r498229b/bin:$PATH \
BISON_PKGDATADIR=~/karen/hostdeps/root/usr/share/bison \
```

## 2026-10-24: karen TWRP cross-validation + fixes

The oneplus-karen-roms TWRP tree (android-12.1, releases 3.7.0_12-0/12-1, Oct 2022 —
it booted) was used to cross-validate and yielded three real fixes, all committed:
1. **Super partition sizes are device-measured (lpdump): 12348030976 / main
   12345933824** — our denniz-inherited values (10200547328) were wrong for karen
   hardware; wrong sizes break the dynamic-partition metadata OTAs write.
2. **prebuilt/kernel must be the gzip blob, not the decompressed Image** (magiskboot
   unpack decompresses; stock boot.img carries ~16.7 MB gzip). LOS BoardConfig now
   uses BOARD_KERNEL_IMAGE_NAME := Image.gz (our build produces it; uncompressed
   Image + ramdisk overflows the 64 MiB boot partition).
3. Their fstab is entry-identical to the OOS13 stock fstab — independent confirmation.
   Their device.mk also documents the real stock OTA partition set (my_* partitions
   plus preloader_raw/lk are flashed by STOCK otas — custom ROMs correctly exclude
   the bootloader chain).

TWRP A13 update: `E:\trees\android_device_oplus_karen-twrp`, branch `android-13`
(commit 2b66d1f amended to f822cac): prebuilts swapped byte-identical to the OOS13
dump (kernel gzip 16.7 MB / dtb 210471 / dtbo 716800), product IDs corrected to
CPH2401, CHANGELOG entry added, original authors (Beanow, SakilMondal, Sathamspot,

## 2026-10-24 incident: WSL outage (IMPORTANT)

Ubuntu WSL's ext4.vhdx lives on `E:\WSL\ubuntu` and E: hit 100% full (25 MB free) while
the kernel clone/toolchain/out grew inside it → ext4 I/O errors → WSL service wedged
("Catastrophic failure", distros won't start). Recovery requires an ADMIN PowerShell:

1. `Restart-Service LxssManager` (or reboot the machine), then
2. Free E: space or relocate the Ubuntu vhd to D: (34 GB free) BEFORE starting the
   distro again:
   `wsl --export Ubuntu D:\wsl-ubuntu.tar` (needs E: headroom first!), or move other
   E: data. Do NOT run `--set-sparse --allow-unsafe` on the possibly-dirty vhd.
3. The in-vhd kernel clone (`~/karen/android_kernel_oplus_karen`, glm branch with the
   same 3 commits) and toolchain are expected intact once the distro boots; the D:\work
   copy is the authoritative backup either way.
4. The device tree repo on E: was left with a wiped index by the crash; it was recovered
   (glm rewritten to a clean 58-file tree + progress doc commit). If anything looks odd,
   `git reset --hard 459afd0` on glm restores the final state.
