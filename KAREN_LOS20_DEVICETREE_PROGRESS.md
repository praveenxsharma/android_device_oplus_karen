# karen LOS20 device tree — progress log

OnePlus Nord 2T (RMX3031/CPH2401/OP557A, codename `karen`), LineageOS 20 / Android 13.
Ground truth for every device value: the A13 OxygenOS dump at `D:\ossi-karen-dump`
(`/mnt/d/ossi-karen-dump` in WSL). Reference (structure only, values must be re-verified
against the dump): `mt6893-development/android_device_oplus_op6893` (denniz, same MT6893
platform but A-only with a recovery partition — karen is virtual A/B, recovery-as-boot).

## Branch layout

- Device tree `glm` branch (this repo): all bring-up commits; `main` stays untouched.
- Kernel `glm` branch in `praveenxsharma/android_kernel_oplus_karen`, based on
  `lineage-23.2` (contains the stock karen defconfig import + prebuilt-dtbo overlay
  disable by praveenxsharma). Local clone: `~/karen/android_kernel_oplus_karen` (Ubuntu WSL).
- Vendor tree: generated by extract-files.py into `vendor/oplus/karen` on the build host.
  Local validation harness: `~/karen/fakeroot` (extract-utils + prebuilts + symlinked dump).

## Verified device facts (from the dump)

- Virtual A/B **with compression**, recovery-as-boot, boot header **v2**, no vendor_boot,
  no cache/recovery partitions. Stock kernel is an **uncompressed Image**, 4.19.191+, clang 11.
- Partition sizes (exact image dumps): boot 67108864, dtbo 716800, super 10200547328,
  main group 10196353024 (system system_ext vendor product odm only — my_* partitions are
  NOT built; fstab keeps their nofail entries).
- Stock fingerprint: `OnePlus/CPH2401/OP557AL1:13/TP1A.220905.001/S.ef7649_3761f:user/release-keys`
  (VENDOR_SECURITY_PATCH 2023-03-05, first API level 31, VNDK 31 / sepolicy 31.0).
- VINTF: 46 HALs; manifest is stock-equivalent (target-level 5). ODM declares radio/mtkradioex/
  secure_element/oplus HALs via manifest_dsds/manifest_ss (ship with the odm image).
- Vendor partition dump was restored from the dump repo git history (`git checkout --
  vendor_extracted system_ext_extracted`) — extraction now finds every blob (2520 entries).

## Known open items

- SELinux is enforcing with minimal device policy + SELINUX_IGNORE_NEVERALLOWS; expect
  denials on first boot. If boot stalls, try `androidboot.selinux=permissive` via
  BOARD_KERNEL_CMDLINE for debugging, then write the policy.
- AOSP/LOS full build is done on the separate build device; this machine only validates
  extraction + kernel compile.
- When pushing: device tree glm + kernel glm + vendor tree (generate on the build host
  with `extract-files.py <dump>`), and push the kernel glm branch so lineage.dependencies
  resolves.
- `__pycache__/`, `build.log`, `output*.txt` are untracked/ignored; keep them out.
